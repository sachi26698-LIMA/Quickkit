# Security & Privacy consolidation plan (pre-route-change audit)

Inventory baseline: 60 category routes: 57 dedicated definitions plus the existing password generator, hash generator and Base64 Developer Tool. The 72-capability inventory overlaps routes; read `SECURITY_PRIVACY_TOOL_INVENTORY.md` for exact real features and limitations. Do not claim the missing HTTPS checker or absent digital signing exists. The following is the complete assignment before changing routes; each existing operation remains its real implementation, not a placeholder.

- Password and hash retain their original canonical URLs because they are already established standalone and hash is also a Developer Tool; their existing workspaces become tabs of the upgraded page. Base64 stays independently available as a Developer Tool at its old URL and is reused in cryptography; no duplicated implementation. These three URLs are not redirected. All 57 dedicated legacy URLs should redirect to the assigned unified route with the precise operation selected; never route arbitrary slugs to guessed tabs. Search keywords must include operation names, and favorites on old dedicated slugs migrate to the unified tool while cross-category Base64 stays available.
- Preserve all existing form logic, privacy disclosures, content validation, results, downloads, batch features, and input/output state isolation. Switching operations clears the previous mounted workspace (including secrets); never persist sensitive content in URLs or storage. Explicit network consent stays in its original workspace; only unified DNS and IP page CSP allows their existing fixed endpoints. No generic URL proxy or live HTTPS/TLS claim. Network results cannot be invented.
- A tabbed wrapper must deep-link from old bookmarks, handle back/forward, keyboard and mobile use, and render correctly after hydration. Metadata and sitemap use unified canonical routes; old slugs are redirected, not indexed. Verify complete one-to-one slug assignment and redirects, all tab operations, files and hashes, consent-based mocks, favorites/search, mobile, full static checks/build and available browser tests. Report remaining restrictions honestly; do not delete old implementation modules or unrelated work.
