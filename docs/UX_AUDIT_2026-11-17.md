## 1. Architecture summary

- **Stack**: Next.js 16 (App Router, Turbopack), React 19, TypeScript, Vitest + Testing Library, Playwright e2e, Supabase (admin-only), Vercel.
- **Rendering**: public pages are ISR (`revalidate = 300`) with a server-side catalogue read that falls back to the shipped static catalogue when Supabase is unavailable.
- **Styling**: one global token sheet `app/globals.css` (21 643 lines) + `app/home-premium.module.css` (homepage colour layer) + `app/tool-pages.css` / `tool-pages.generated.css` (per-tool surfaces) + `components/admin/admin.module.css` (admin has its own design system with light/dark themes).
- **Client code**: header, search, tool workspaces, favorites (`localStorage`), feedback (`localStorage`), admin shell.
- **Tool count**: 42+ published tools across 8 categories, every route preserved.

## 2. Prioritized UX issues

### Critical usability

| # | Issue | Evidence |
| --- | --- | --- |
| C1 | **The advertised global search shortcut is inert on most pages.** `Ctrl/⌘+K` and `aria-keyshortcuts` are declared on every search input, but only `/` and `/tools` mount one. On any tool page, category page or info page the shortcut silently does nothing. The header search icon is a two-step journey (navigate → `#tool-search` → focus). | `components/hero-search.tsx`, `components/tool-explorer.tsx` (duplicate keydown handlers); no listener elsewhere |
| C2 | **Three competing palettes, none of them the brand palette.** The public shell uses a warm blush/plum scheme (`--background: #fdf7f5`, `--plum: #3b1b4f`, `--rose: #d6598f`), the homepage overrides it with a third violet set (`#5b21b6 / #6d28d9 / #a21caf` in `home-premium.module.css`), while the Admin panel already uses the target brand violet/cyan (`#7828d8`, `#35c6d0`). The requested brand palette (Deep Plum `#27103F`, Violet `#7828D8`, Rose `#F04F9B`, Background `#F7F5FC`, Text `#241638`) appears nowhere on the public site. | `app/globals.css:1-40`, `app/home-premium.module.css:1-40`, `app/admin/admin.css:26-40` |
| C3 | **Search suggestions are shallow and only half-accessible.** Matching covers name/description/keywords only (no category or “function” match), results stop at 5 with no way to arrow through them (`ArrowDown` jumps to the first link; no `aria-activedescendant`, no `role=combobox/listbox/option`), no visible result count for sighted users, no recent or example queries to seed an empty box. | `components/hero-search.tsx:110-140`, `components/tool-explorer.tsx:120-165` |

### High-impact improvements

| # | Issue | Evidence |
| --- | --- | --- |
| H1 | **`/tools` filter state is not URL-synced.** Inbound `?q=`/`?category=` is honoured, but typing or tapping a category chip never writes back to the URL — filters are lost on refresh, and back/forward cannot restore them. | `components/tool-explorer.tsx:236-260` (read-only `useSearchParams`) |
| H2 | **No visible result count, sort, or clear-filters on `/tools`.** The count exists only as `sr-only`; nine category chips render with no “clear” affordance once a filter is active; no sort order control. | `components/tool-explorer.tsx:167-196` |
| H3 | **No recently-used tools anywhere.** Favorites (heart → `/saved`) exist and are privacy-correct (`localStorage`), but the homepage and directory never surface “continue where you left off”, so repeat visitors re-find tools from scratch. | homepage `app/(public)/page.tsx` (no recent section) |
| H4 | **No example searches in the hero.** The brief calls for useful example searches; today only a placeholder string hints at query shape, and the empty search panel shows a single sentence. | `components/hero-search.tsx:96-99`, `:168-176` |

| H6 | **Duplicated search logic.** Hero search and tool explorer each re-implement hydration gating, `⌘K` handling, hash-focus, matching and ranking — two copies to keep in sync. | both files, `useHydrated` calls |

### Advanced UX opportunities

| # | Opportunity | Value |
| --- | --- | --- |
| A1 | **Global command palette** (⌘K everywhere): search tools + jump to categories/saved/help from any page. | Solves C1 with one component; the expected premium-SaaS pattern. |
| A2 | **Recent searches** stored in `localStorage` (privacy-conscious, per-browser), shown when the box is empty, with a clear control. | Fewer keystrokes for repeat queries; complements favorites. |
| A3 | **Example query chips** in the empty search panel (“merge pdf”, “qr code”, “json”, “compress image”). | Teaches query shape without cluttering the hero. |
| A4 | **URL-synced explorer state + sort + clear** (H1/H2). | Shareable, restorable, bookmarkeable directory state. |
| A5 | **Recently-used tools row** on the homepage (client-only, `localStorage`, renders nothing when empty). | Real repeat-visit value; no server tracking. |

### Accessibility (WCAG 2.2 AA review)

Strong baseline already: skip link, semantic landmarks, `aria-current` navigation, `aria-pressed` filters/favorites, visible `:focus-visible` rings (3 px), `prefers-reduced-motion` honoured in every animation module, 16 px mobile inputs (no iOS zoom), 44 px+ touch targets, `role=status` live regions for copy feedback.

Gaps found:

| # | Gap | Fix |
| --- | --- | --- |
| A11y-1 | Search inputs are not proper comboboxes (`role`, `aria-expanded`, `aria-controls`, `aria-activedescendant`, listbox/option roles missing); arrow-key traversal of results is incomplete. | Rebuild both panels on the ARIA combobox pattern (also fixes C3). |
| A11y-2 | Header `Escape` handler always focuses `.menu-button`, which is `display:none` on desktop — focus call is a no-op at best. | Only move focus when the button is visible. |
| A11y-3 | Breadcrumb last crumb is a plain `<span>` without `aria-current="page"`. | Add `aria-current` in `ToolShell`. |
| A11y-4 | New feature surfaces (command palette) must be a labelled dialog with focus trap, Escape and focus restoration. | Built into A1. |

### Mobile & responsive

- Breakpoint coverage is extensive (90 `@media` blocks): header collapses at 860 px with a full-width menu, search becomes 58 px tall, kbd hints hide, grids drop to 2/1 columns, footer to 2 columns.
- Verified statically: no known horizontal-overflow sources; e2e geometry specs (320→1920 px) exist and assert `scrollWidth == clientWidth` — they cannot execute in this sandbox (browser download blocked), so real-device verification remains an owner action.
- Gaps: hero popular-chip row can wrap awkwardly below 359 px; no `overflow` guards were needed elsewhere; sticky elements are minimal (good).

### Performance

- Homepage HTML ≈ 272 KB / tools ≈ 528 KB (inlined RSC payload with the display-projected catalogue — already optimised via `toClientTools`); hero art is CSS-animation heavy but pauses offscreen and respects reduced motion; no layout-shifting images (dimensions declared).
- Risks to avoid while redesigning: do not ship the full catalogue into new client components, do not add animation libraries, keep ISR intact.

### Admin panel

- Separate, competent design system (`admin.module.css`, 17 breakpoints, light/dark toggle, brand-violet focus rings already `#7828d8`), resource tables with filters, confirm dialogs, live context, empty/loading/error states — covered by 17 admin test files (all green).
- Findings: no changes required for correctness; light polish only (keep scope on public site where the UX debt is).

### Duplicated / inconsistent patterns

1. Search logic duplicated (hero vs explorer) — extract shared hooks.
2. Breadcrumb markup repeated in three shapes (ToolShell, `/tools`, category pages) — visual consistency maintained via one `.breadcrumbs` class; JSON-LD differs per page so the markup stays per-page, only the shell styling is shared.
3. Empty states: `.empty` class is consistent across explorer/categories/tool panels — keep.

## 3. Prioritized execution plan

1. **Design tokens** → apply the brand palette to `:root`, shadows, gradients, homepage layer, hero screen accent, OG image (C2, V1–V6).
2. **Homepage + navigation** → brand headline treatment, example searches, recently-used row (H3, H4, A3, A5, V1–V2).
3. **Search & discovery** → ARIA combobox panels, keyboard traversal, recent searches, global command palette, URL-synced explorer with count/sort/clear (C1, C3, H1, H2, H6, A1–A4, A11y-1).
4. **Tool pages** → shell polish: breadcrumb `aria-current`, title block rhythm, consistent focus/feedback (A11y-3, H5).
5. **Mobile & accessibility fixes** → header Escape, touch/contrast verification against the new tokens (A11y-2, A11y-4).
6. **Admin** → audit-only unless a defect appears (tests already cover responsive/flows).
7. **Regression QA** → full Vitest, TypeScript, ESLint, Prettier, production build, route smoke; e2e documented as owner action.

## 4. Constraints honoured

- No tool removed, renamed or re-routed; no URL, SEO metadata, Supabase integration, auth, RLS or environment variable touched.
- No new runtime dependencies; no fake statistics, testimonials or trust badges; no server uploads introduced.
- Existing test expectations that encode intentional copy/colour changes are updated only where the change is deliberate, keeping their regression intent (admin tagline must not drive hero copy; hero geometry unchanged).
