# Word to PDF V5 — fixtures and evidence

Everything in this folder is produced by the shipped code path; nothing is hand-made.

## `fixtures/quality.docx`

A synthetic Word package that exercises heading styles, bold/italic/underline/colour,
bulleted and nested numbered lists, a shaded table header, an embedded PNG, right
alignment, a page break, a landscape section, and Gujarati + Devanagari paragraphs.
Its header contains live `PAGE` and `NUMPAGES` fields; its footer is centred.

Regenerate it deterministically:

```bash
npm run fixture:word-to-pdf
# → docs/word-to-pdf/v5/fixtures/quality.docx
```

The generator is `scripts/word-to-pdf-v5-fixture.mjs` (uses the `docx` dev dependency).
Because it is generated by `docx` rather than Word, it is a layout fixture, not a
reference for Word's exact pagination.

## `evidence/`

| File | What it is |
|---|---|
| `engine-page1.png` | Page 1 as produced by the built-in renderer, no export overlays |
| `engine-page3-landscape.png` | The landscape section, showing inherited header, footer and page field |
| `api-export-page1.png` | The same document after `POST /api/word-to-pdf` applied header, footer, numbering, watermark, background and metadata |
| `api-export-page3-landscape.png` | Landscape page with the applied overlays |

Reproduce the raw pages:

```bash
npx vitest run tests/word-to-pdf-render.test.ts   # asserts the content shown here
```

Reproduce the export variant: see §7 of `docs/WORD_TO_PDF_V5_SETUP.md` (smoke test) and
run the same POST with `header`, `footer`, `numbering`, `watermarkText`, `title` and
`author` in `x-quickkit-settings`.

The measured 100–1000 page ladder lives in `test-results/word-to-pdf-v5-stress.json`
and is summarised in `docs/WORD_TO_PDF_V5_QA.md` §5.
