# Word to PDF V2 — pre-change audit (4 November 2026)

The existing route, consent-gated NDJSON endpoint, bounded sequential batch loop, native LibreOffice adapter, ZIP/download utilities and PDF.js preview are retained. The V1 UI is a two-column upload form plus a modal; changes currently invalidate output and require a full upload. The native adapter currently mixes native rendering with PDF overlays, and PDF previews repeatedly reopen bytes. No LibreOffice executable is installed in this environment. The operator enablement/security gate and provisional 100-page limit remain unchanged.

V2 plan: factor the existing PDF post-processing into one shared pure module, used by the native adapter and browser live updates. Add an opt-in raw-native response mode (old endpoint behavior stays compatible). Keep one retained native base per file; regenerate selected pages/overlays/metadata locally with a serialized, debounced queue. Native page layout, image export, font and rendering-option changes require a fresh explicit conversion; optionally auto-refresh only with separate, revocable auto-upload consent. Stale outputs cannot be exported. Every export downloads the exact bytes shown by preview. No simulated pages, document statistics or file-size estimates.

Original DOCX comparison uses actual docx-preview HTML rendering, labelled approximate, never claimed to be a Word reference render. Validate/sanitize packages before rendering them locally; reject remote resources and strip navigation. Before/after compares the retained native PDF with the exact final PDF. PDF canvas navigation/zoom/thumbnails reuse the existing openPdfPreview handle; text search is on-demand, bounded and cancellable. Thumbnails are lazily rendered. Revoke object URLs and destroy handles on replacement/unmount.

Selected-page layout is a distinct PDF geometry adjustment after pagination, not selective Word reflow: explicitly disclose the difference. Native full-document layout applies to sections before pagination. Native font embedding and document tagging are capability-dependent; PDF subsetting/geometry edits may degrade document-level navigation/structure. Print Quality remains high-quality image export, not PDF/X or CMYK certification. Native fidelity/stress QA is still a release blocker, not masked by UI mocks.
