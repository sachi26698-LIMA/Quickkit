# Administrator recovery: release blockers

This PR is not approved for production until real isolated end-to-end and security checks pass.

- Production recovery uses the fixed apex origin only on Vercel production; preview and local development require their own explicit origin. Preview must use a separately approved HTTPS origin, isolated Supabase project and exact callback allowlist entry. Requests on any other origin fail closed. The browser that requested recovery must open the email link because PKCE verifier cookies are host- and browser-bound.
- The request path uses the existing shared, atomic submission limiter RPC for separate HMAC-derived IP and email buckets (four attempts per 15 minutes each). Its IP bucket is checked first. Vercel requests use only `x-vercel-forwarded-for`; missing IP, credentials or storage causes a 503. Confirm the deployed ingress cannot bypass Vercel header sanitization. Local development shares one IP bucket. Email buckets allow targeted temporary denial of recovery; review operational mitigations.
- Both eligible and other addresses generate the same PKCE verifier state and schedule a post-response task. Only eligible tasks dispatch to Supabase; provider latency is outside the public response path. Dispatch uses Next.js `after` and is best effort, not a durable delivery queue: runtime failure may lose a request. Provider delivery, statistical timing behavior, and platform `after` execution remain unverified in the protected preview. Do not claim timing leakage is impossible or email delivery is guaranteed.
- The application now consumes a keyed proof fingerprint using a unique database insert before attempting a password update. Concurrent attempts should permit only one; failed updates require a new recovery link. The migration has not been applied or tested on an isolated Supabase project. Mocked concurrent tests do not prove actual database isolation, token invalidation or end-to-end replay rejection.
- The automated invalid/expired/reused tests use simulated provider errors. They do not demonstrate real email delivery, expiry, replay rejection, password update, or subsequent login. Test with an authorized isolated administrator and mailbox, never production users.
- Vercel preview protection and the sandbox network restriction have prevented actual deployed-browser testing. Do not weaken these protections to obtain a passing check.
