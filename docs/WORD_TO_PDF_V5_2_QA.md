## 1. What was wrong in V5.1

| #   | Defect                                                                                                                          | User-visible symptom                                                           |
| --- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 1   | `w:spacing w:line="276" w:lineRule="auto"` was read as 13.8 pt of absolute leading instead of a 1.15 multiplier                 | Lines drawn on top of each other, text looked "compressed" and smeared         |
| 2   | Whole ZIP members were rejected when the member _path_ looked like a macro (`word/vbaProject.bin` check applied to every entry) | Real documents failed to open at all                                           |
| 3   | Table borders and shading were only read from `w:tblPr` direct formatting                                                       | Tables from styles (`TableGrid`) rendered with no grid and no header fill      |

| 5   | Numbering-level indentation (`w:lvl/w:pPr/w:ind`) was ignored                                                                   | Bullets sat on their own line, body text indented to a random default tab stop |
| 6   | `\t` inside a run was collapsed to a space; right-aligned tab stops unsupported                                                 | Resume dates (`2021 — present`) jammed against the job title                   |
| 7   | Text in text boxes (`w:txbxContent`) was only parsed in one code path                                                           | "Funky chicken" test box lost its text                                         |

All seven are fixed in `lib/tools/word-to-pdf/render/{ooxml,render}.ts` and are
covered by regression tests.

## 2. How quality is measured now

`tests/word-to-pdf-v5.2-quality.test.ts` converts every document in
`docs/word-to-pdf/v5.2/corpus/`, `…/corpus/real/` and the V4 fixtures, writes each
PDF to `test-results/word-to-pdf-v5.2/`, and then measures the _output_:

- page count and page size from `PDFDocument`;
- extracted text spans, baselines and font sizes via `pdfjs-dist`;
- **overlap pairs** — two spans on the same page whose boxes intersect both
  horizontally (>2 pt) and vertically (>55 % of the smaller font size);
- **blank pages** — pages with no extractable text;
- **font-size sanity** — nothing below 6 pt or above 96 pt;
- **images** — `OPS.paintImageXObject` count;
- **text coverage** — squashed (whitespace-free, lower-case) characters found in
  the PDF divided by characters stored in `document.xml`/`header*/footer*`.

Hard gates: overlaps = 0, blank pages = 0, 6 ≤ size ≤ 96, coverage ≥ 0.92.

`tests/word-to-pdf-v5.2-text.test.ts` is the stricter, per-run audit: **every**
`<w:t>` of ≥ 4 characters must be findable in the PDF, with two documented
exceptions (a `U+0085` line-separator run in `sample-docx.docx`, and a duplicated
header string), plus an explicit opt-out for Indic runs because PDF text
extraction re-orders vowel signs (the glyphs _are_ drawn — see
`evidence/f-fonts-p1.png`).

## 5. Preview

`lib/tools/pdf-to-word/preview-pdf.ts` opens the produced PDF with `pdf.js`
(`doc.numPages`, `doc.getPage(n)`), and `components/tools/word-to-pdf/preview-resources.tsx`
renders every page lazily through an `IntersectionObserver` (`WindowedPages`, 90 px
thumbnails). A page is rendered when it scrolls into view — nothing is skipped and
nothing is approximated from the DOCX; the preview is the same byte array the
download button saves.

## 6. What is still not verified, and why

- **Browser/E2E:** `npx playwright install chromium` fails in this sandbox
  (`Error: Download failure, code=1`), there is no system Chrome, so the
  Playwright specs remain collect-only here. The HTTP-level checks in §4 exercise
  the same route the browser calls, but **no real browser rendered the UI in this
  session** and I am not claiming otherwise.
- **LibreOffice fidelity:** `soffice` is absent and `deb.debian.org` is
  unreachable, so the native worker path cannot be exercised. The app reports
  `native: false` and the engine label says "built-in" for that reason.
- **Indic text extraction:** the glyphs render, but PDF text extraction returns
  visual-order codepoints, so automated substring checks skip those runs.
- **Chart/SmartArt/equation content** is not laid out. Charts are surfaced as a
  warning and are counted as missing text; they are the main reason the coverage
  threshold is 0.92 rather than 1.00.


Outputs land in `test-results/word-to-pdf-v5.2/` (not committed). Evidence
screenshots and sample PDFs under `docs/word-to-pdf/v5.2/` are committed.
