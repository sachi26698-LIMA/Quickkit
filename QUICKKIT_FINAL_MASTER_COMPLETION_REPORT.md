## Supabase project, schema, migration and data audit

Read-only connector inspection selected the existing Supabase project `Quick_kit` (`oevjmxcoyibkonousdoh`); Auth, database and REST reported `ACTIVE_HEALTHY`. The migration ledger lists exactly:

- `202611100001_quickkit_account_data` — version `20261113045854`.
- `quickkit_master_admin` — version `20261114190425`.

Both are already applied once. Do not reapply, duplicate, reset, or create another project/migration for this integration. The public schema has nine expected `quickkit_*` tables: profile/favorites; contact/feedback submissions and limiter; tool/category overrides, site settings and Admin activity. Database catalog reads confirmed primary/foreign/check constraints including stable slug keys, bounded metadata fields, allowlisted setting keys, valid submission statuses, and foreign keys to `auth.users` for actor/updater identity. No row content was read. The one profile row was left untouched.

RLS is enabled on all nine tables. The live catalog shows explicit browser-role deny policies on `quickkit_admin_activity`, `quickkit_admin_category_overrides`, `quickkit_admin_site_settings`, `quickkit_admin_tool_overrides`, `quickkit_contact_submissions`, `quickkit_feedback_submissions`, and `quickkit_submission_limits`; profiles and favorites have self-scoped authenticated policies. These catalog observations do not replace actual JWT/PostgREST tests. `service_role` is privileged and bypasses RLS by design; the app keeps it in `server-only` modules and calls it only after Admin session verification for protected API operations. The live tests performed this turn were read-only metadata and row-count queries only.

### Database-backed paths in the application

- **Catalog/categories:** `quickkit_admin_tool_overrides` and `quickkit_admin_category_overrides` store sparse overrides over the version-controlled static tool/category catalogue. Public server rendering filters disabled/unpublished records and validates public fields; browser code does not query private override tables directly. Category additions are supported as persisted custom categories. Arbitrary new executable tools are not dynamically implemented from Admin because tool implementations/routes are code-defined.
- **Admin settings:** `quickkit_admin_site_settings` supports the explicitly validated website name, tagline, contact email, social/footer links, announcement, maintenance notice and homepage-content fields. Public layout/home/contact consumers read supported settings on the server. The live settings table is empty, so propagation was not demonstrated.
- **Tool/category management:** the API edits the static tool catalogue and can publish/unpublish/enable/feature items; it can create custom categories, edit visibility/order and soft-archive categories with zero assigned tools. The Admin tools table now has a separately confirmed Archive action that disables and unpublishes an existing tool while retaining its code-defined catalogue record; Reset overrides remains a distinct action. No “create tool” API/UI exists. Mock-backed component and API tests cover these controls; live saves remain unverified.
- **Private submissions:** contact and feedback forms use validation, same-origin checks, HMAC bucket rate limiting and server-side inserts. Admin inboxes use protected reads and constrained status/notes/type updates plus individually confirmed deletes. The live tables contain zero rows; no synthetic row was inserted or inspected.
- **Activity/security:** audited Admin mutations write `quickkit_admin_activity`; dashboard/security pages query database status and configuration flags without returning secret values. The activity table is empty; no real Admin mutation was exercised.
- **Visitor statistics:** this is not Supabase-backed. `lib/visitor-analytics.ts` uses libSQL/Turso through `ANALYTICS_DATABASE_URL` and optional `ANALYTICS_DATABASE_TOKEN`, with its own aggregate/session tables and server-capped updates. These variables are absent from local runtime and no matching Vercel project entries appeared in metadata; visitor-stat persistence is therefore not configured/verified. The endpoint fails closed with 503 when unavailable.
- **Legacy account tables:** profile/favorites are not used for the public experience (visitor account UI is disabled and favorites remain browser-local). The existing single profile row was counted only; do not clean it up without explicit owner review.
